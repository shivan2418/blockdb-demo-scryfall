# Static Scryfall Demo — Design

**Date:** 2026-07-24
**Status:** Approved (pending spec review)

## Purpose

A demo application that showcases [`static-shard`](/home/emil/Programming/static-shard) — a
zero-backend library that queries large static datasets directly in the browser. The demo is a
Scryfall-like Magic: The Gathering card browser built entirely on static files: search, filter,
sort, and view 116,138 cards with **no API and no server**, deployable to GitHub Pages.

The app is the vehicle; the star is static-shard. Every user-facing feature should map to a real
query through the generated typed client.

## Context

- **Data:** Scryfall bulk `default-cards` — 116,138 records. Source JSONL is 532 MB (input only,
  not deployed).
- **Shards (built):** `public/shard-data/` — 722 MB, 529 shards, manifest + secondary indexes.
  Largest single shard ~2 MB.
- **Generated client:** `src/shard-db/{client.ts,schema.ts}` — regenerated by `static-shard build`.
  The current build indexes **essentially every field**, giving a full query surface.
- **API surface:** `db.<collection>.findMany({ where, orderBy, limit, offset }) → { records, hasMore }`,
  `.count(where) → { count, exact }`, `.get(id) → Rec | null`.

### Query constraints discovered in the built schema

These shape the UI and are non-negotiable (enforced by the type system):

1. **Only `image_updated_at` has range operators** (`gt/gte/lt/lte`). `cmc`, `edhrec_rank`, and
   `released_at` expose only `equals`/`in`/`not`. → Numeric filters are **discrete multi-select**,
   not sliders.
2. **`orderBy` works on any indexed field** regardless of its operators. → Sort by name, released_at
   (newest), edhrec_rank (popularity), cmc, rarity all work.
3. **`not` cannot be the only constraint** in a `where` (`RiderGuard` — compile error). → The data
   facade never emits a `not`-only `where`.
4. **`maxResults` ceiling is 10,000** (client guardrail). → Always page; page size ≤ 60.
5. **`count()` is an approximate upper bound** except for an empty `where` (exact recordCount) and
   pruned-to-zero (exact 0). → Totals are labeled approximate; empty state is driven by `count === 0`
   (which is trustworthy).

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Feature scope | Full Scryfall-like | Search + faceted filters + sort + detail + set browsing |
| Rendering | Client-side SPA, static files | Truest showcase of static-shard's in-browser model |
| Host | GitHub Pages | Static-only; drives base-path + routing decisions |
| Visual | Original clean design | Own styling, not a pixel clone |
| Router | HashRouter | Bulletproof on GH Pages — no 404.html redirect hack |
| Numeric filters | Discrete multi-select | Range operators unavailable except `image_updated_at` |

## Architecture & Routing

Client-side React SPA (Vite). Deployed to GitHub Pages via GitHub Actions.

- **HashRouter** — avoids server-rewrite requirements on Pages.
- **Vite `base`:** `/shard-test/` (repo name).
- **static-shard `basePath`:** derived as `` `${import.meta.env.BASE_URL}shard-data` `` so it resolves
  correctly both locally (`/shard-data`) and on Pages (`/shard-test/shard-data`).

Routes:
- `/` — Browse: search bar + filter panel + results grid + pagination. **All filter/sort/page state
  is encoded in the URL** for shareable links.
- `/card/:id` — Detail via `get(id)`.

## Components & Modules

### Data layer (`src/data/`) — isolates the generated client
- `client.ts` — singleton `connect({ basePath })`.
- `cards.ts` — facade hiding the `default-cards-<timestamp>` collection key. Public:
  `searchCards(filters, sort, page)`, `countCards(filters)`, `getCard(id)`. Internal: `buildWhere`,
  `buildOrderBy`. Invariants: page size ≤ 60; never emits `not`-only `where`; wraps `ShardError` into
  friendly errors.
- `url-state.ts` — encode/decode `{ filters, sort, page }` ↔ `URLSearchParams`.
- `card-view.ts` — pure helpers: image URL resolution (incl. double-faced `card_faces`), mana-cost
  string → pip tokens.

### UI components (`src/components/`, `src/routes/`)
`SearchBar` (debounced) · `FilterPanel` (Colors WUBRG+colorless, Type chips + free text, Rarity,
Mana value multi-select, Set searchable select, boolean toggles: reprint/promo/digital) ·
`SortSelect` (name / newest / popularity / cmc / rarity) · `CardGrid` + `CardTile` (lazy images) ·
`Pagination` (prev/next + approximate total) · `ResultSummary` · `CardDetailView` (image w/ DFC flip,
mana pips, oracle text, P/T or loyalty, set + rarity, artist, prices, legalities grid, link to
`scryfall_uri`) · `ManaSymbol` renderer · loading skeleton / empty / error states.

## Query Behavior & Correctness

- Debounce search 250 ms; ignore stale responses via a latest-request-id guard (no flicker on fast
  typing).
- `cmc` "7+" expands to `in: [7, 8, …, max]`.
- Result totals rendered as approximate ("~12,345 cards"); empty state uses exact `count === 0`.

## Error Handling

- Facade catches `ShardError` (fetch failures, `LIMIT_EXCEEDED`) → user-facing messages.
- Image load failures fall back to a placeholder tile.
- Detail route: `get(id)` returning `null` → "card not found" state.

## Images (DEFERRED)

Hotlinking Scryfall's CDN (`cards.scryfall.io`) is poor form and not the final answer. For the
initial build, the grid/detail will read the record's image URLs to get pixels on screen, but
**self-hosting or proxying card images is an explicit later task**, not part of the first
implementation. Design note: image URL resolution is centralized in `card-view.ts` so swapping the
source later touches one module.

## Testing

- **Vitest unit tests** for pure logic: `url-state` round-trip, `buildWhere` mapping (including
  RiderGuard-safe output), mana-cost parser.
- **One data-layer smoke test** with an injected `fetch` reading local `public/shard-data` — verifies
  a known query returns a known card.
- Full flow verified in-browser.

## Deploy

GitHub Actions workflow: `pnpm build` → upload `dist/` (includes `public/shard-data`) →
`actions/deploy-pages`. `.gitignore` the 532 MB source `.jsonl`.

## Out of Scope

- Scryfall syntax search (`c:red t:instant`) — structured filters only for v1.
- User accounts, decks, collection tracking.
- Self-hosted/proxied images (deferred, see above).
- Pixel-faithful Scryfall styling.
